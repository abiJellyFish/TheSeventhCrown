## 约定
- 默认中文回复，UI、文案、注释使用中文；代码、命令、变量名、文件路径保持英文；文件内容不出现emoji、表情
- 结论先行，简洁直接，不谄媚，不刻意夸赞
- 提供真实判断，方案有问题直接指出，发现更好做法主动说明
- 确保输出有事实依据，不要编造答案，如果找不到答案，直接说不知道
- 在实际修改文件前，先说明方案和风险
- 在修改用户主动添加的内容前，询问用户
- 每次修改内容后，补充修改的原因和方案到项目目录下的 修改日志.md，附上时间戳

## Git
- 在新的项目目录中，自动初始化本地仓库，并询问是否需要关联远程仓库
- 不自动 `git commit` ，在文件发生修改后询问我是否需要提交。提交前先展示将要提交的变更摘要， commit message 使用简洁英文
- 不自动 `git push` ，除非我明确要求
- 不要提交敏感内容，比如接口密钥

## 红线操作
以下操作在任何模式下，执行前必须先询问我：
- 删除文件、目录或 git 历史
- 修改 `.env`、密钥、token、证书、CI/CD 配置
- `git push`、`git rebase`、`git reset --hard`、强制推送
- 公开发布（`npm publish`、生产部署等）
