# 修改方案 7 — X 观察模式修复

---

## 问题

非输入模式下按 X 后没有进入观察模式：报错 `TypeError: 'set' object is not subscriptable`，右侧栏无变化，方向键没有变成观察光标。

## 根因（两个，均已修复）

### 根因 1（崩溃）：`_render_observe` 把 set 当 dict 用

`fov_cache` 的类型是 `set[tuple[int, int]]`（`compute_fov` 返回 set，`game_state.py:50` 声明为 `set`），但 `_render_observe` 第 713 行写了：

```python
light = self.state.fov_cache[cursor]  # set 不可下标访问！
```

这导致 `TypeError`，`RightPanel.render()` 崩溃，观察模式无法渲染。

修复：改为 `in` 成员检查，显示"可见"/"不可见"替代光照等级。

### 根因 2（双重触发）：Binding + on_key 各调用一次 toggle

`action_toggle_observe()` 被调用两次：

| 次序 | 触发点 | 效果 |
|------|--------|------|
| 1 | `Binding("x", "toggle_observe", priority=True)` | `observe_mode = True` |
| 2 | `on_key` 中 `if event.key == "x"` | `observe_mode = False` |

`priority=True` 的 Binding 先触发，然后 `on_key` 再触发，两次 toggle 抵消。由方案6"补充修复 问题A"引入 — 在 `on_key` 加了 X 处理但没删 Binding。

修复：删除 BINDINGS 中的 X 绑定，保留 `on_key`（天然满足"输入模式不响应快捷键"约束）。

## 补充需求（2026-08-08）

### 需求 1：大写 X（Shift+X）触发观察模式

`on_key` 和 `GameInput._on_key` 中判断从 `"x"` 改为 `"X"`。输入模式下 Shift+X 也被 GameInput 拦截。

### 需求 2：地图上显示观察光标

`MapView.render()` 中：当 `observe_mode` 为 True 且 `observe_cursor` 在当前视口内时，该格用反色（reverse）渲染，玩家一眼就能看出正在观察哪一格。

光标始终在视口内（移动光标时自动扩展视口范围确保光标可见）。不需要闪烁，静态反色即可清晰标识。

## 方案

### 改动 1：`_render_observe` — 修复 set 下标访问

```python
# 修复前：
if cursor in self.state.fov_cache:
    light = self.state.fov_cache[cursor]          # TypeError!
    ...

# 修复后：
if cursor in self.state.fov_cache:
    lines.append("亮度: 可见")
else:
    lines.append("亮度: 不可见")
```

### 改动 2：BINDINGS — 删除 X 绑定

删除：
```python
Binding("x", "toggle_observe", "观察", priority=True),
```

### 改动 3：`on_key` — X 改为大写

```python
if event.key == "X":
    self.action_toggle_observe()
    event.stop()
    return
```

### 改动 4：`GameInput._on_key` — x 改为 X

```python
def _on_key(self, event: Key) -> None:
    if event.key == "X":
        event.stop()
        return
    super()._on_key(event)
```

### 改动 5：`MapView.render()` — 观察光标渲染

渲染循环中，当当前格等于 `observe_cursor` 时，用 `reverse` 样式：

```python
# 在 MapView.render() 的渲染循环中，每个格子的样式判断末尾：
obs_cur = self.state.observe_cursor if self.state.observe_mode else None
...
# 判断完 terrain/entity 后：
if (col, row) == obs_cur:
    # 用 reverse 样式覆盖
    ...
```

需要确保视口范围能容纳观察光标。当前视口以玩家为中心，半径 `r+2`。观察光标只能在 FOV 内移动（`_move_player` 中限制 `(nc, nr) in self.state.fov_cache`），FOV 半径 = `vision_range`。视口半宽 = `(r+2)/2`。当光标在 FOV 边缘时可能超出视口。

**视口扩展**：计算视口时，若处于观察模式，将光标坐标纳入视口范围计算，确保光标始终可见：

```python
if self.state.observe_mode:
    oc, oro = self.state.observe_cursor
    ox = max(0, min(ox, oc - vw // 2))
    oy = max(0, min(oy, oro - vh // 2))
    ox = max(0, min(ox, gmap.width - vw))
    oy = max(0, min(oy, gmap.height - vh))
```

实际上更简单的做法：直接以光标和玩家的中间点作为视口中心，或直接扩展边界确保光标在视口内。

**最简方案**：在观察模式下，视口以光标为中心而非玩家，因为观察时光标才是关注焦点：

```python
if self.state.observe_mode:
    cx, cy = self.state.observe_cursor
else:
    cx, cy = pc, pr
ox = max(0, min(cx - vw // 2, gmap.width - vw))
oy = max(0, min(cy - vh // 2, gmap.height - vh))
```

> 采用玩家中心 + 确保光标在视口内的方案更好（玩家仍想看到自己的位置）。光标反色显示已足够醒目。

**采用方案**：视口仍以玩家为中心，但扩展边界确保光标在视口内：

```python
ox = max(0, min(pc - vw // 2, gmap.width - vw))
oy = max(0, min(pr - vh // 2, gmap.height - vh))

# 观察模式：确保光标在视口内
if self.state.observe_mode:
    oc, oro = self.state.observe_cursor
    ox = min(ox, oc)
    oy = min(oy, oro)
    ox = max(ox, oc - vw + 1)
    oy = max(oy, oro - vh + 1)
    ox = max(0, min(ox, gmap.width - vw))
    oy = max(0, min(oy, gmap.height - vh))
```

光标格渲染：在已有样式基础上叠加 `reverse`：

```python
# 在 append 之后，对光标格追加 reverse 样式
obs_cur = self.state.observe_cursor if self.state.observe_mode else None
...
if (col, row) == obs_cur:
    # 保存当前 text 长度，回退两个字符重新用 reverse 样式 append
    ...
```

实际上 Rich Text 不好回退。更简单的方式：在 append 之前判断，如果是光标格就用不同样式。

```python
cursor_style = " reverse" if (col, row) == obs_cur else ""
# 在每个 append 的 style 后追加 cursor_style
```

## 待解决问题（2026-08-08）— 暂不修改

### 问题 A：地图格子双字符渲染导致水平移动视觉偏移

**现象**：地图每个格用两个字符渲染（`@ ` / `. ` / `##` / `" "` 等），方向键在网格上移动 1 格，屏幕光标跳 2 个字符位，视觉上像是"一次走两格"。

**根因**：`MapView.render()` 中为模拟正方形格子（终端字符宽高比约 2:1），每个逻辑格占 2 个屏幕字符宽 × 1 行高。

**方案**：改为单字符渲染，每格 1 字符 × 1 行。

改动点：
- 实体：`{ch} ` → `{ch}`
- 地形：`ch * 2` → `ch`
- 玩家：`@ ` → `@`
- 门：`ch * 2` → `ch`
- 空不可见格：`"  "` → `" "`

需同步调整：视口宽度 `vw` 翻倍以保持视野范围不变（原来是 `r+2` 列，每列 2 字符宽；改为单字符后需 `(r+2)*2` 列）。

影响文件：`render/textual/app.py`（`MapView.render` 约 10 处字符拼接修改）

### 问题 B：快捷键上下文泄漏 — S 键在战斗面板中触发法术

**现象**：战斗子面板（select_action / select_target / select_maneuver / select_special）中按 S，日志输出 `[法术] 此功能待开发`。这些面板上根本没有 `[[S]]法术` 这个选项。

**根因**：`priority=True` 的 Binding 在 Textual 中优先于所有 widget 触发，不经过 `on_key` 的上下文检查。`action_show_spells` 无条件执行，没有检查当前面板是否显示 `[[S]]`。

**类似问题全面审计**：

所有 `priority=True` 绑定分为几类：

| 分类 | 绑定键 | 问题 |
|------|--------|------|
| **致命** — 在任何面板都触发 | `Q`（退出） | 战斗子面板中也能退出游戏 |
| **噪音** — 在不该触发时打印日志 | `S`（法术）、`/`（击晕）、`B``Z``K``Y``H``M``E`（法术书/制作/烹饪/炼药/高度/地图/系统） | 全部打印"此功能待开发"，在战斗子面板中纯属干扰 |
| **副作用** — 在不该触发时执行操作 | `r`（短休）、`R`（长休）、`g`（慢速）、`G`（疾走）、`,`（消磨） | 有战斗 guard 但仍打印"战斗中无法XX"，在战斗子面板中应静默 |
| **双重触发** — Binding + on_key 各调一次 | `0`-`8`（交互/探查/躲藏/协助/跳跃/撤离/回避/推撞/擒抱） | idle 模式下每个数字键触发两次动作；战斗子面板中 Binding 单次触发 |
| **无害** — 可在任何面板使用 | 方向键、`Esc`、`X`（已修复）、`:`（输入）、`F5``F9`（存档）、`C``I`（角色/物品栏）、`shift+tab`（结束战斗轮）、`A`（攻击） | 无问题 |

**双重触发详情**（`0`-`8`）：

```
idle 模式: Binding(priority=True) 先触发 action_N()
         → on_key 再匹配 digit_actions[N] 再触发一次
         → 例如按 1 触发两次 action_1()，日志输出两条相同消息

战斗子面板: Binding(priority=True) 触发 action_N()
           → on_key 中 phase != "idle" → return（不触发第二次）
           → 但仍然触发了一次，不应该触发
```

**方案思路**（供后续方案详细设计）：

两种方向：

A. **action 方法内增加上下文 guard** — 每个 action 开头检查当前面板是否列出该快捷键。改动分散但精确。

B. **统一上下文分发** — 删掉大部分 `priority=True` 绑定，改为在 `on_key` 中根据当前面板上下文统一分发。集中管理但改动量大。

| 面板 | 允许的键 |
|------|---------|
| 探索默认 | 0-8, /, g, G, r, R, ,, A, S, X, Q, C, I, B, Z, K, Y, H, M, E, Esc, 方向键 |
| 战斗默认 | 同上 + shift+tab |
| 攻击方式 (select_action) | A0-A4, Esc, X, C, I |
| 选择目标 (select_target) | T0-Tn, Esc, X, C, I |
| 选择战技 (select_maneuver) | A0-An, Esc, X, C, I |
| 特殊行动 (select_special) | A0-A3, Esc, X, C, I |
| 物品栏 (inventory) | C, I, Esc, X |
| 角色面板 (character) | C, I, Esc, X |
| 输入模式 | 无快捷键（已满足） |

影响文件：`render/textual/app.py`（BINDINGS + on_key + 各 action 方法，改动量较大）
