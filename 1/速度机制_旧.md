整个系统的核心思想只有一句话：

  ▎ 钟摆是统一的时间货币，速度决定时间能换多少距离。

  拆开来讲：

  ---
  钟摆（pendulum_count） 是全局时钟。每推进 1 钟摆，意味着"一段标准时间过去了"。所有周期效果（buff 过期、持续伤害、AI
  决策）都挂在这个钟摆上，不挂在任何角色的 curS 上。

  ---
  curS 的意义：curS 是每个角色身上的"里程表"。它回答一个问题——在钟摆流逝的过程中，这个角色应该走多少格？

  - curS 单位是"格子"，带小数部分
  - maxS 单位是"格子 / 钟摆"，即 1 钟摆能走多少格
  - 每次钟摆推进 delta 拍，角色里程 += maxS × delta
  - curS 每跨过 1.0、2.0、3.0... 这些整数线，就触发一次实际移动机会
  - curS 对 maxS 取余，因为 curS 本质上是个循环计数器——它只关心"相对上一次整数边界的位置"

  ---
  为什么要取余 maxS 而不是 SCALE 尺度上的某个值？

  之前我搞混了。curS 的"格子"和 SCALE 的"时间刻度"是两条线：
  - SCALE 是时间的精度单位（确保 1/3、1/7 等分数能整除）
  - curS 是距离的累积，跨越的整数线是 1 格、2 格、3 格...

  所以正确的做法是：

  // curS_ticks 存储的是"格子 × SCALE"
  // 即 curS_ticks / SCALE = 真实的格子数

  old_tiles = curS_ticks / SCALE;                    // 整数除法：之前跨过了几格
  curS_ticks += maxS * delta * SCALE;                // 累加距离
  new_tiles = curS_ticks / SCALE;                    // 现在跨过了几格
  crossed = new_tiles - old_tiles;                   // 本次跨过了几个整数格子
  curS_ticks %= maxS * SCALE;                        // 对 maxS 取余（循环）

  为什么取余 maxS × SCALE 而非 SCALE？

  因为 curS 的周期是 maxS。一个 maxS=3 的角色，每 3 格为一个完整"移动单位"。curS=0 和 curS=3
  在这个角色的视角下是同一个相位。取余 maxS×SCALE 就是在 SCALE 精度下实现"对 maxS 取余"。

  ---
  为什么需要 old

  因为 crossed 取决于累加前后跨越的整数线数量，不能只看增量。

  反例：

  curS_ticks = 2000（= 0.79 格，SCALE=2520）
  delta = 0.4 钟摆，maxS=3
  增量 = 3 × 0.4 × 2520 = 3024（= 1.2 格）
  新 curS_ticks = 2000 + 3024 = 5024（= 1.99 格）

  crossed = 5024/2520 - 2000/2520 = 1 - 0 = 1

  跨过了 1.0 整数线，触发 1 格移动。

  如果只看增量：3024 / 2520 = 1，这次碰巧也对了。但：

  curS_ticks = 2000（= 0.79 格）
  delta = 0.1 钟摆，maxS=3
  增量 = 3 × 0.1 × 2520 = 756（= 0.3 格）
  新 curS_ticks = 2756（= 1.09 格）

  crossed = 2756/2520 - 2000/2520 = 1 - 0 = 1

  增量只有 0.3 格，756 / 2520 = 0。但因为之前的 0.79 加上 0.3 跨过了 1.0 线，实际触发了 1
  格移动。增量法漏算了旧的小数部分。

  所以 old 是必要的——它保留了累加前 curS 的整数部分（跨过了几个整数线），用来和累加后的做差。

  ---
  回应各点

  1. 为什么有 old：见上。old 是为了精确计算"累加前后跨越了几个整数线"。只用增量会丢失之前攒的小数部分。

  最终精简伪代码

  const int SCALE = lcm(1..max_possible_speed);

  struct Character {
      int maxS;          // 移动等级
      int curS_ticks;    // 里程累积，范围 [0, maxS*SCALE)
      bool canMove;      // 是否可移动（状态标记）
  };

  // 全局
  int pendulum_count = 0;
  int pendulum_acc_ticks = 0;

  // ── 玩家移动一格 ──
  void playerMove(Char& c, Dir d) {
      if (!c.canMove) {
          // 不可移动：时间照走，人不动
          pendulum_acc_ticks += SCALE / c.maxS;
          tickPendulum();
          return;
      }
      c.moveOneTile(d);
      c.curS_ticks += SCALE;
      c.curS_ticks %= c.maxS * SCALE;
      pendulum_acc_ticks += SCALE / c.maxS;
      tickPendulum();
  }

  // ── 多人选中移动 ──
  void partyMove(vector<Char*>& party, Dir d) {
      Char* leader = findSlowest(party);  // maxS 最小者
      playerMove(*leader, d);             // 主控走，钟摆按主控推进
      for (auto* f : followers(party)) {
          f->followToNear(leader);        // 寻路到主控邻格
          f->curS_ticks += SCALE;
          f->curS_ticks %= f->maxS * SCALE;
      }
  }

  // ── 休息 ──
  void playerRest() {
      pendulum_count++;
      advanceNPCs(1.0);
      triggerPendulumEvents();
      // curS 不变
      // pendulum_acc_ticks 不变
  }

  // ── 钟摆推进（按键触发）──
  void tickPendulum() {
      while (pendulum_acc_ticks >= SCALE) {
          pendulum_count++;
          pendulum_acc_ticks -= SCALE;
          advanceNPCs(1.0);
          triggerPendulumEvents();
      }
  }

  // ── NPC 推进 delta 个钟摆 ──
  void advanceNPCs(double delta) {
      // 拍快照：所有 NPC 基于当前地图状态规划路径
      vector<NPCMovePlan> plans;
      for (auto* npc : npcs_sorted_by_maxS_desc) {
          int old_tiles = npc->curS_ticks / SCALE;
          if (!npc->canMove) continue;  // 不可移动：curS 冻结
          npc->curS_ticks += npc->maxS * (int)(delta * SCALE);
          int new_tiles = npc->curS_ticks / SCALE;
          int crossed = new_tiles - old_tiles;
          npc->curS_ticks %= npc->maxS * SCALE;
          plans.push_back({npc, crossed});
      }
      // 执行移动：路径被更快 NPC 占据则停在最后可通行格
      for (auto& plan : plans) {
          plan.npc->executePath(plan.crossed);
      }
  }

```
┌─────────────────────────────────────────────────────────────┐
│                    第一阶段：计算移动额度                      │
│                                                             │
│  所有 NPC 按 maxS 降序排序（同 maxS 按 ID 排序）              │
│                                                             │
│  基于移动前的地图状态拍快照，各自规划路径                      │
│                                                             │
│  for each NPC:                                              │
│    if npc.canMove == false → 跳过，curS 冻结                 │
│                                                             │
│    old_tiles = npc.curS_ticks / SCALE     // 整数，累加前   │
│    npc.curS_ticks += npc.maxS × delta × SCALE              │
│    new_tiles = npc.curS_ticks / SCALE     // 整数，累加后   │
│    crossed = new_tiles - old_tiles        // ≠ floor(增量)  │
│    npc.curS_ticks %= npc.maxS × SCALE                       │
│                                                             │
│  ┌─ 为什么用 old 做差而不用增量 ─────────────────────────┐  │
│  │                                                      │  │
│  │  curS=0.79格, delta=0.1钟摆, maxS=3                  │  │
│  │  增量=3×0.1=0.3格, 756/2520=0 → 增量法: 0格 ❌       │  │
│  │  0.79+0.3=1.09 → 跨过1.0线 → 做差法: 1格 ✓          │  │
│  │                                                      │  │
│  │  old 保留了累加前"已经跨过了几根整数线"的信息          │  │
│  │  加上增量后，新旧线的数量差 = 本 tick 应走格数         │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                    第二阶段：执行移动                          │
│                                                             │
│  for each NPC（按第一阶段排序）:                              │
│    按规划路径依次走 crossed 格                               │
│                                                             │
│    for step in 1..crossed:                                  │
│      目标格 = path[step]                                    │
│      if 目标格已被更快的 NPC 占据:                           │
│        停在 path[step-1]（最后一个可通行格）                 │
│        剩余步数丢弃，不重新寻路                               │
│        break                                                │
│      else:                                                  │
│        移动到目标格                                          │
│                                                             │
│  // 路径基于快照，不因前面 NPC 的移动而重新规划               │
│  // 被挡 = 浪费，下一轮钟摆再规划                             │
│                                                             │

═══════════════════════════════════════════════════════════════
                      核心数据流
═══════════════════════════════════════════════════════════════

  玩家按方向键/休息
     │
     ▼
  pendulum 推进 ──→ triggerPendulumEvents()  ← 周期效果唯一入口
     │                 (buff过期/持续伤害/AI决策 都挂这里)
     ▼
  NPC curS += maxS × delta × SCALE
     │
     ▼
  crossed = (新curS的整数部分) - (旧curS的整数部分)
     │
     ▼
  NPC 移动 crossed 格（可被阻挡，丢失不补偿）
     │
     ▼
  curS %= maxS × SCALE  （循环，保留小数部分进入下一轮）

  时间 → 钟摆 → 比例 → 累加到curS → 跨整数线 → 移动
         ↑                    ↑
    全局统一时间        每个角色按自己的maxS换算
```

---
-  核心三层总结

| 层 | 做什么 | 单位 |
|----|--------|------|
| **钟摆层** | 统一计时、驱动周期事件 | `pendulum_count` |
| **curS 层** | 每个角色按自己的 maxS 把时间换算成"里程" | `curS_ticks ∈ [0, maxS×SCALE)` |
| **移动层** | curS 跨过整数线 → 获得移动格数 → 寻路 → 执行 | `crossed = new_tiles − old_tiles` |

- delta
 delta 是本次推进的钟摆数。在当前的 advanceNPCs(1.0) 调用中，delta 始终为 1.0。

  公式拆解

  npc.curS_ticks += npc.maxS × delta × SCALE
                   ───────── ───── ─────
                      ↑        ↑      ↑
                速度(格/钟摆)  钟摆数  精度单位

  - npc.maxS = 3 表示"1 钟摆走 3 格"
  - delta = 1.0 表示"过了 1 个钟摆"
  - 3 × 1.0 × 2520 = 7560，即本 tick 累积了 7560 个精度单位 = 3 格里程

  为什么保留 delta 参数而不是硬编码 1.0

  当前两处调用都是 advanceNPCs(1.0)：

  ┌──────────────────────────────────┬───────┐
  │             调用位置             │ delta │
  ├──────────────────────────────────┼───────┤
  │ tickPendulum() 的 while 循环体内 │ 1.0   │
  ├──────────────────────────────────┼───────┤
  │ playerRest()                     │ 1.0   │
  └──────────────────────────────────┴───────┘

  留 delta 参数只是为了扩展性——如果未来某个机制需要一次性推进半拍或多拍（比如某个技能"加速时间流动 2 钟摆"），可以直接
  advanceNPCs(2.0)。
